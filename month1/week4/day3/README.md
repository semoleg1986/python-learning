# 🔹 День 3 — Pull Request и Code Review

## 🧠 Теория

### Что такое Pull Request (PR)

Pull Request (PR) — это запрос на слияние изменений из одной ветки в другую
(обычно из feature/... → main).
Используется для просмотра, обсуждения и проверки кода перед объединением.

*Как создать Pull Request на GitHub*

1. Закоммить изменения в своей ветке:

        ```bash
        git add .
        git commit -m "feat: добавил обработку ошибок"
        git push origin feature/day3
        ```
    
2. Перейди на GitHub → твой репозиторий:
   - Нажми “Compare & pull request”
   - Укажи:
       - 	base: main
       -	compare: feature/day3
       -	Добавь описание, цель PR, скриншоты при необходимости.

3. Нажми Create Pull Request.

*Стиль сообщений коммитов (Conventional Commits)*

| Тип       | Назначение                         | Пример                               |     
|-----------|------------------------------------|--------------------------------------|
| feat:     | Новая функциональность             | feat: добавил модуль аналитики       |
| fix:      | Исправление ошибки                 | fix: корректная обработка исключений |
| docs:     | Документация                       | docs: обновил README                 |
| refactor: | Рефакторинг без изменения логики   | refactor: оптимизировал цикл         |
| test:     | Добавление/изменение тестов        | test: добавил тесты для API          |
| style:    | Форматирование, правки без логики  | style: убрал лишние пробелы          |


*Основы Code Review*

-	💬 Пиши понятные комментарии: «Можно использовать list comprehension для краткости»
-	✅ Одобряй, если всё ок: LGTM (Looks Good To Me)
-	🔄 Проси изменения при необходимости: «Переименуй переменную для читаемости»
-	🔒 Не мерджи PR без review, если проект командный.
